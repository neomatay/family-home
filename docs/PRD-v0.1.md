# 「家」· v0.1 PRD

**一句话**：两个人和三只猫的家庭协作操作系统；v0.1 点亮厨房，其他房间灰暗待点亮。

## 用户与核心循环

- 用户：同住的两个女生（v0.1 同设备切换成员，v0.2 起各自设备协作）
- 核心循环：**上架菜 → 预定今晚吃什么 → 自动查冰箱 → 缺料进购物清单 → 接单 → 完成（做过 N 次）**

## v0.1 范围

**做**：菜单上架（菜名/材料/份数 + 营养估算）、会做标记、预定（日期/时间/谁做/待接单）、冰箱库存（食材/日用品/猫用，低库存圆点）、购物清单（缺料自动生成 + 手动添加）、首页矢量小家（房间导航 + 状态圆点）

**不做（二期池）**：拒绝换人流转、多菜组合一餐、体重健康、猫猫模块、账本、菜品照片、真实 AI 估算、推送通知、多设备同步

## 美术与交互架构

- 首页 = 矢量剖面小家（代码绘制）：厨房亮灯，状态一律圆点/角标，无彩色条纹
- 房间内页 = 克制卡片工具风；层级 ≤2（家 → 房间）
- 背景层与交互层分离：未来可整体替换为 AI 插画皮肤（明暗两张），热区坐标不动
- 明暗双主题；375px 基准；无 hover 依赖（为小程序迁移预留）

## 数据模型（v0.1 本地存储，结构与 Supabase 目标表同构）

| 表 | 关键字段 |
|---|---|
| families | id, name, invite_code |
| members | id, family_id, name, color |
| dishes | id, family_id, name, servings, ingredients(jsonb), nutri{k,p,c,f}, est(bool), cooks[], times_cooked, by |
| inventory | id, family_id, name, cat(food/daily/cat), qty, unit, low |
| reservations | id, family_id, dish_id, date, time, cook_id(null=待接单), status |
| shopping | id, family_id, name, note, done, by |

## 营养估算

上架表单内「估算营养」按钮：按材料 + 份量计算每份 kcal/蛋白/碳水/脂肪，可手动微调，标记「估算」徽章。v0.1 为本地食物库估算（明确标注）；接入后端后换真实 AI，交互不变。

## 二期池（按优先级）

1. Supabase 接入 + 家庭邀请码（两人各自手机真实协作）
2. 拒绝/换人流转、一餐多菜
3. 猫猫管家（档案/体重/疫苗/猫粮库存）
4. 健康（体重体脂曲线，关联"吃了多少"）
5. 账本房间；AI 插画皮肤
